# 永豐企業風格 HTML 簡報系統（sinopac-deck）

把任何金控內部報告做成「直向滑動、一頁一張 16:9」的 HTML 簡報：
投影可全螢幕播放、手機可直式閱讀，還能放 PPT 做不到的互動元件。
本文件定義不可違反的版型引擎、品牌外框規格、官方色守則與版型庫。
**這是通用系統，不綁任何題目**——任何部門、任何報告類型都套同一套。

## 工作流程（v4：模型只寫文字，HTML 由腳本組裝）

**為何這樣分工**：v3 的痛點是輸出額度大量耗在樣板 HTML 上（一副 12 頁的 S2 約吃掉
2–3 萬 token 在讀模板與搬 HTML），內容被排擠、長輸出末段品質衰減。v4 起 HTML
一律由 `scripts/build_deck.py` 生成——**模型從頭到尾只產出文字稿**，
一次對話即可完成整副（20 頁內），token 全數花在內容判斷上。

**S0 骨架**（判斷工作）
讀完素材後只產出 `storyline.md`：每頁一列（頁碼｜版型｜data-label｜頁標題｜本頁回答的問題）。
頁標題一律判斷句／行動句。交付前自跑「串讀測試」：只讀頁標題欄須構成完整論證。
>10 頁或素材模糊時，**經使用者核可後才進 S1**；短小明確的案子可 S0＋S1 併一輪直接出稿。

**S1 文案**（判斷工作，本管線唯一的重輸出）
依 `references/writing.md`（必讀，含行數預算表）逐頁把全部文字寫進 `content.md`，
格式見 `references/content-example.md`；槽位規格查 `build_deck.py --schema <版型>`。
逐條自審：字數帶＋行數預算（60–90% 填充）、結論列非複述、同清單句式與行數一致、
禁詞不得裸用。**本階段與其後都禁止手寫 HTML**（blank 版型的自訂圍欄除外）。

**S2 組裝**（零 token 機械步驟）
```
python3 scripts/lint_content.py content.md          # 字數／行數／密度／禁詞
python3 scripts/build_deck.py content.md -o deck.html
```
lint 有 ✗ 就回 S1 改文字，**不是在 S2 縮字級**。腳本自動處理：引擎複製、頁碼、
頁尾注入、結論列上色、卡片 3/4 格與主從（lead）網格、占位字檢查。
手動模式（僅 blank 自訂版面或腳本外的特殊需求）：自訂樣式只寫 `<style id="deck-custom">`
（content.md 的 `# custom-css` 圍欄會自動注入），引擎 `<style>`／`<script>` 唯讀。

**S3 驗收**（機械工作）
開 `deck.html?debug` 看溢出告警（超框頁會標紅框＋console 警告）；跑文末完工檢查表
＋ 1080p／手機／列印三檢。

**省 token 鐵則**：`assets/template.html` 與產出的 `deck.html` **不要整檔 Read**
（檔尾 logo base64 約 15KB≈4k token）；查版型用 `--schema`，查頁面用 grep 或部分讀取。
LOGO 由 CSS 變數單源供應（檔尾 `style#brand-assets`）；換新 logo 只改那一行。

**樣板是起點，不是枷鎖**：可在品牌框架（外框／官方色／字級下限 .78em／16:9）內自由組合、
混搭元件、用 `blank` 空白版自創版面，讓內容決定版式。唯一硬底線＝**不跑版**：
過 16:9 溢出檢查（1080p 無捲軸、手機直立正常、列印一頁一張；`?debug` 可開溢出告警）。

## 一、核心引擎（不可違反）

理由：投影全螢幕時版面要撐滿、字級要等比放大。違反任一條，就會重現
「投影只剩中間一張小卡、字超小」的災難。

- 垂直 scroll-snap，一個 `<section class="slide">` 一張。
- 16:9 框架公式，**嚴禁加 max-width 上限**：
  ```css
  .frame{aspect-ratio:16/9;width:min(100%,calc((100vh - 32px) * 16 / 9));container-type:size}
  ```
- 等比字級：`.inner{font-size:clamp(12px,2.6cqh,38px)}`。框內一律用 **em**，嚴禁混用 px 字級
  （1080p 全螢幕時基準字約 27px，整張隨投影面積等比縮放）。
- 全片最小字級 **.78em**（1080p 投影約 ≥20px）。標題 2.2–2.5em、內文 .84–1em、標籤 .78em。
- `.inner` 預設 `overflow:clip`；內容偏密的張加 `.scroll`。
- 固定 chrome：右側圓點導覽（可點跳頁、hover 顯示頁名）、頂部進度條、
  鍵盤 ↑↓／空白／PgUp·Dn／Home／End 翻頁、進場 reveal 動畫。

**版面層級（每張必守，這是和「AI 味」的分界）**

- 四級層級：區塊標題（`.blk-h`，可配 icon）＞ 關鍵字（`.lv-k`，放大上色）＞ 內文 ＞ 註解（`.lv-n`，小灰字）。**每個資訊區塊至少做出兩級**，標題約為關鍵字的 1.5 倍。
- 主從、忌等分：少用 `1fr 1fr` 與四張等大卡片（最明顯的 AI 指紋）；改用 `.split`（1.5fr/.9fr）或「一大數小」。
- 每張一個焦點：指定一個最大元素（`.hero` 大數字／大關鍵詞）當主角，其餘弱化。內容少時放大焦點或補 icon／線條，**別讓區塊飄在空白裡**。
- icon 收口：區塊標頭與清單（`.ilist`）前綴一致風格的單色圖示，活潑但克制。

## 二、品牌外框（自官方母片換算的相對座標）

母片基準 33.87 × 19.05 cm。以下為必守規格：

| 元素 | 規格 | 母片來源 |
|---|---|---|
| LOGO（內頁） | 右下角；右緣收在版面寬 ~97%；落在底部 ~95–97% 高度帶（v4 貼邊瘦身，釋放內容高度）；**寬 ≤ 版面寬 21%**（範本用 ~8%） | 物件 4 |
| LOGO（封面） | 左上角；寬 ≤ 版面寬 ~18% | 標題版面 |
| 品牌標語 | 左下「翻轉金融 共創美好生活 Together, a better life.」；**寬版一行**（英文用斜體 serif 接在中文後）、**窄版／手機自動拆中英兩行** | 物件 1 |
| 頁碼 | 最左下；小方框 chip；**只放數字**（01、02…，不加總頁數、不加斜線） | 物件 3 |
| 標題紅線 | 標題下方、近滿寬（兩側 ~3–5% 邊距）、落在頂部 12–16% 高度帶 | 物件 2 |

**LOGO 鐵則**：相對位置不可動；尺寸**只能更小、不可更大**；logo 為深色字，
**深色背景上一律墊白色圓角底座**（無底座不可讀）。淺色面用去背透明版直接貼。

## 三、官方色使用守則

| token | 色值 | 角色 |
|---|---|---|
| `--brand` | #D03238 | 官方紅＝**行動／強調**／招牌紅線 |
| `--brand-deep` | #A82329 | 深一階紅：小字級的紅、hover |
| `--brand-soft` / `--brand-bg` | #E58B8F / #FBE9EA | 紅的淡化：漸層尾端／表面水洗 |
| `--blue` | #003F98 | 官方藍＝**結構／輔助／現況** |
| `--blue-soft` / `--blue-bg` | #3A63AC / #E8EDF7 | 藍的淡化 |
| `--canvas` | #0B1322 | 頁面畫布（深藍夜色＋紅藍微光暈） |
| `--paper` 系 | #EDF0F4… | 卡片紙面（冷調淺色，非純白） |

鐵律：
1. **中性色佔約七成**版面；紅藍只做點綴，不做大面積底色。
2. 表面（卡片底、區塊底）用 6–8% 淡化版；**全彩只給細線、小標籤、強調塊**。
3. 小字級的紅一律用 `--brand-deep`（#D03238 當小字對比不足）；藍在白底對比足夠，可直接當文字色。
4. **紅藍不可大面積相鄰**（高彩度互振），中間以留白或中性隔開。
5. 紅藍要有語意分工：紅＝行動／重點／新作法；藍＝結構／現況／流程。同一張內不要等量競爭。
6. 背景不必全白：畫布用深藍夜色、淺色卡片浮在其上；**封底建議深藍反白頁**（官方藍衍生漸層、紅當提示色）。
7. **強調分兩個方向**：強化＝關鍵字上色（`.k` 紅／`.kb` 藍）、淡底（`.mark`，品牌紅淡底）；弱化＝次要資訊轉灰（`.mute`）。長段落用這組做出抓手，不要整段灰平。
8. **例外**：焦點數字／`hero` 大數字可用大號品牌色，這是刻意的視覺主角；`.mark` 一律用品牌紅淡底，**不引入第三色（黃、綠等）**。

## 四、線條母題（紅線的延伸語彙）

同一個「紅線」意象的四種變奏，依情境取用（範本內皆有實作）：

1. **header 紅線**：左端粗段（brand-deep）＋向右淡出細線（brand → 透明），
   進場時由左向右畫出（scaleX 動畫，粗段先、細線跟上）。
2. **封面中線**：標題下方置中、兩端淡出的細紅線。
3. **封面角落線組**：右上「紅粗段＋藍細線＋灰髮絲線」三層右對齊，當裝飾。
4. **封底引言記號**：紅粗段＋淡出線，置於金句上方。

新增自訂裝飾時，沿用這個語彙（水平線、粗細對比、單端淡出），不要引入新的幾何語言。

## 五、版型庫（template.html 內各一張；槽位規格查 `build_deck.py --schema <版型>`）

**結論列（v4）**：所有內容版型在標題下固定配一條 `.bluf` 結論列（1–2 行的
「所以呢＋下一步」；「請示／行動／決議」自動轉紅）。寫法見 writing.md §〇。

| 版型 | 何時用 |
|---|---|
| `cover` 封面 | 標題＋報告人＋日期 |
| `agenda` 議程 | 3–8 個段落的目錄 |
| `divider` 章節隔頁 | 章節切換、節奏停頓（大號章節數字） |
| `compare` 雙欄對照 | 任何 A vs B：現況/改善、方案比較（藍＝現況、紅＝行動） |
| `cards` 卡片陣列 | 3–4 個並列重點（紅藍 stripe 區分類型）；首格可標 `lead` 做主從、破等分 |
| `kpi` 數字頁 | 3–4 個關鍵指標，進場數字滾動；首格可標 `lead` 放大當視覺主角 |
| `table` 表格頁 | 清單、進度表、比較表（藍色表頭＋狀態 chip） |
| `matrix` 2×2 定位矩陣 | 優先序、市場定位、風險／報酬等四象限（顧問常用） |
| `case` 案例頁 | 背景/痛點 → 做法 → 產出；含可複製指令框（選用，展示指令/操作時才留） |
| `prose` 文字密集 | 政策解讀、背景說明等大段論述放不進稀疏版型時；雙欄結構化內文 |
| `timeline` 流程/時程 | 階段性流程、里程碑（橫向 4–5 步） |
| `optiontabs` 方案切換（互動） | 方案／情境比較，點頁籤切換，主從版面＋優缺對照（v4 起支援同副多個實例） |
| `quote` 觀點頁 | 大引述、核心判斷，節奏停頓用（serif 大字） |
| `ask` 決議頁 | 請示／決策事項 2–4 條＋右欄關鍵條件（時限/預算/範圍）；內部報告最關鍵的一頁（v4 新增） |
| `closing` 深色封底 | 收束金句＋白底座 logo |
| `blank` 空白畫布 | 既有版型都不合、要自訂版面時；只有品牌外框，內容自由發揮（配 `# custom-css` 圍欄） |

內容密度準則：一張一個論點；**密度雙向管制**——字數帶管單行不爆、行數預算管版面不空
（完整預算表見 writing.md §二之二；lint 會警告過疏/過密）。雙欄對照每側 ≤5 條；
卡片 ≤4 張（說明寫 2–5 行，別只給一行）；表格 ≤7 列；超過就拆頁、`scroll: 1`、
或改 `prose`／`blank`。

## 六、HTML 優勢（節制使用）

PPT 做不到、值得用的：方案／情境切換（tabs）、一鍵複製指令、進場線條繪製、
KPI 數字滾動、hover 提示、**`<details>` 收合**（完整但次要的內容）、**hover 白話 tooltip**（名詞解釋，取代滿頁括號）。
原則：**一副簡報 1–2 個互動點**即可；互動要服務內容，不是炫技。
嚴禁 localStorage／sessionStorage；狀態一律放 JS 變數。

## 七、手機直立 fallback（必改清單，缺一就跑版）

桌面版大量使用容器高度單位（cqh），手機**不能只縮小，必須整組改寫**。
範本的 `@media screen and (max-aspect-ratio: 13/10)` 已內建以下全部規則，自訂版型時勿破壞：

- 放掉 16:9：`aspect-ratio:auto`、`container-type:normal`、自然高度往下捲、關 scroll-snap。
- 所有 cqh／cqw 尺寸（內距、logo 高、頁尾定位）換**固定 px**；基準字固定 16px。
- 絕對定位元素（頁尾帶、封面左上 logo、角落線組）改回正常文件流或隱藏。
- 線條動畫、reveal 全部關閉（`transform:none`）。
- 標語拆中英兩行；多欄 grid 全改單欄（寬 ≥560px 的平板可放兩欄）。
- 圓點導覽隱藏。

## 八、列印／PDF（滿版 16:9 分頁）

同一份檔可直接列印或存 PDF：檔面左下「列印／PDF」鈕，或 Ctrl／Cmd+P。

- `@media print` 已設 `@page{size:33.87cm 19.05cm;margin:0}`（16:9 母片尺寸），**一張投影片＝滿版一頁、邊到邊無留白**。
- v3 起輸出即 16:9 滿版 PDF（去除舊 A4 橫式的置中留白與邊框）；若確需 A4，改 `@page` 的 size 即可。
- 列印對話框務必勾選 **「背景圖形 / Background graphics」**，否則底色與品牌色不會印出（已加 `print-color-adjust:exact` 盡量強制）。
- `beforeprint` 會自動把 KPI 數字補成最終值、把所有 `<details>` 攤開，`.tip` 白話轉成括號內文；列印後自動還原。
- 深色封底會印成整頁深色（耗墨）；若需大量影印，可臨時把 `closing` 改淺色版。

## 九、文字規格（摘要；完整規格與正反例見 references/writing.md，S1 階段必讀）

0. **結論先行（BLUF）**：整副先講結論，每頁 `.title` 即該頁結論，內文只給證據；讀完標題列須拿到完整主張＋建議。
1. **標題＝判斷句**：每頁 `.title` 必須是有主詞、有立場的完整判斷或行動句（12–22 字），
   禁止主題標籤（「客群分析」✗ →「南區『富有企業主』輪廓與存款數據不符」✓）。
2. **串讀測試**：只讀全副頁標題，須構成完整論證。讀不通＝故事線壞了，回 S0。
3. **一頁一問**：每頁只回答一個問題；說不出「這頁在主張什麼」就砍頁。
4. **同清單同句式**：同一組條列全名詞句或全動詞句，長度差 ≤8 字；前置關鍵字須為
   內容詞（主詞／數字／結果），禁範疇詞（「重要性」「效益面」✗）。
5. **數字優先**：有數字寫數字；禁用「顯著／大幅／有效」代替數據。
6. **禁詞不得裸用**：賦能、打造、優化、強化、深化、落實、推動、致力、攜手——
   必須帶受詞＋數字或具體機制，否則改寫。
7. **標題與內文不互相複述**：標題講結論，內文給證據。
8. **台灣人話**：對外用台灣用語與全形標點，無中國用語（視頻→影片、質量→品質…）、無翻譯腔；數字／專有名詞／法遵承諾一字不改、不自行編造數字（借鏡 speak-human-tw，完整見 references/writing.md §六）。

| 元素 | 字數帶 × 行數 | 句式 |
|---|---|---|
| 頁標題 `.title` | 12–22 字 × 1 行 | 判斷句／行動句 |
| 結論列 `bluf` | 24–70 字 × 1–2 行（v4 內容頁固定配備） | 標題的補完：後果＋行動 |
| 章節眉標 `.kicker` | ≤10 字 | 「NN · 章名」 |
| 區塊／面板標 | ≤8 字 | 名詞短語 |
| 條列每條 | 10–22 字（1 行）／26–48 字（2 行）；同清單行數一致 | 前置粗體關鍵字 2–6 字 |
| 卡片說明 | 28–70 字 × 2–5 行（別只給一行） | ≥2 個資訊點：機制＋數字 |
